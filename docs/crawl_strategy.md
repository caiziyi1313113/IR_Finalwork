# 如何高效抓取 10 万条

## 1. 目标拆解

如果只抓首页和少量详情页，很难达到 `100000` 条。更现实的做法是：

- 多子站点并行抓取
- 列表页驱动详情页发现
- 详情页继续发现附件链接
- 历史归档页补足长尾内容

## 2. 先抓什么

优先级建议如下：

1. 南开大学新闻网的新闻列表与归档页
2. 各学院“通知公告/新闻动态/学术活动/下载专区”
3. 教务处、本科招生、研究生招生、研究生院等高密度信息站点
4. 页面内出现的 PDF、DOCX、XLSX 等附件

## 3. 怎样保证礼貌抓取

- 每个 host 单独限速，默认 `1.5` 秒以上
- 每个 host 并发数控制在 `1~2`
- 进入新 host 前先请求 `robots.txt`
- 对失败请求做指数退避，不做无限重试
- 对同一 URL 做规范化和去重，避免重复抓取

## 4. 如何提高效率

- 采用异步抓取，而不是串行 `requests`
- URL 只允许在给定白名单 host 内扩展
- 优先保留正文页、正文页中的附件、列表翻页链接
- 对图片、视频、压缩包等非文本资源直接跳过
- 快照和结构化记录分开存，避免反复解析原网页

## 5. 10 万条从哪里来

可计入索引的记录应包括：

- HTML 页面
- PDF / DOC / DOCX
- XLS / XLSX
- PPT / PPTX

在多学院、多年份、多栏目并行抓取时，达到 `10 万` 条并不依赖超高并发，而是依赖：

- 足够多的站点入口
- 完整的归档页覆盖
- 附件全文抽取

## 6. 风险点

- 部分站点是模板页，URL 参数很多，容易重复抓取
- 部分附件文件名重复，需要用 URL 哈希做本地命名
- 部分网页正文编码不统一，必须统一转成 UTF-8
- 文档类附件体积大，建议先做大小阈值与超时控制
